# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository state

Early-stage monorepo with two independent projects (no root build tooling; root `README.md` is empty):

- `api/` — Go module `api` (`go 1.27.2`), the laptop daemon `sharingd`. The laptop is the only server (HTTPS, self-signed cert pinned by fingerprint); the phone is always a client. Packages under `internal/`: `config` (settings, peers, TLS identity), `pairing` (single-use invites to peer tokens), `protocol` (ws messages), `server` (routes, bearer auth, ws hub), `discovery` (mDNS `_sharing._tcp`), `transfer` (resumable upload sessions, ranged downloads, persisted offers, folder manifests, tar for old clients, limits), `control` (unix-socket API used by the CLI), `retry` (the one retry policy), `clipboard`, `service` (systemd unit, file-manager entries). `cmd/sharingd` is split into `run.go` (daemon), `cli.go` (subcommands over one `call` helper), `doctor.go`, `notify.go`. Design and roadmap: `docs/plan1.md` to `docs/plan4.md`.
- `mobile/` — Expo / React Native app (Expo SDK 58, React 19.3, RN 0.88, TypeScript, bun lockfile). Source is under `mobile/src/` (`app/` routes: `index` status, `setup` one-time pairing with fingerprint review, `permissions`; `components/` Button, Step, ErrorBanner; `lib/` invite parsing, permission hooks and the status hook; `theme.ts`). Native code is the local Expo module `mobile/modules/sharing-service` (Kotlin: foreground service; `Session` websocket and reconnect with mDNS discovery and a pinned-TLS client; `Transfers` persistent SQLite queue with two workers, `Uploader`/`Downloader`/`Remote` for the resumable protocol, `Retry` policy, `ClipSync`; MediaStore Downloads storage (files land in Downloads/<laptop name>), share target with a URI policy, boot receiver, clipboard tile; the device token is wrapped by an Android Keystore key in `Vault`). It must run without JS, so keep logic in Kotlin and the module a thin bridge; its `AndroidManifest.xml` is merged into the app (no config plugin). Build-dependent permissions and `allowBackup=false` come from `mobile/app.config.ts` (`SHARING_AUTO_CLIPBOARD=1` adds `READ_LOGS` and the overlay permission for the opt-in automatic clipboard). `mobile/android/` is generated by prebuild and gitignored.

## Workflow rules

- Never put co-author lines, the Claude name, or "generated with" notes in commits, PRs, or any other artifact.
- Flow per change: branch, code, test, commit (descriptive message), PR, merge into `main`. Never delete branches after merge, locally or on the remote.
- Ask the user when design decisions are open.
- Stop any services/processes started during work (dev servers, daemons, emulators) before finishing.

## Product goal

AirDrop-like sharing between a Linux laptop and an Android phone over WiFi: files, folders, images, videos, plus automatic two-way clipboard sync over websocket. The app is opened only once for setup (pairing, permissions); received files are filed automatically in a folder named after the sender; afterwards both sides run as always-on background services with mDNS discovery (no fixed IPs) and a pairing-code-derived shared key. Chosen design: Go daemon in `api/` run as a systemd user service; Android via the Expo app plus a custom Kotlin foreground-service native module (needs a development build, not Expo Go).

## Commands

`make help` lists everything; `make test` runs both test suites, `make lint` the style checks (golangci-lint, prettier, ktlint), `make bench` the Go benchmarks.

API (run from `api/`):

```bash
go run ./cmd/sharingd run          # SHARING_CONFIG_DIR overrides ~/.config/sharing
go run ./cmd/sharingd pair|peers|send [--to peer] [--wait] <path>|transfers|doctor
go build ./...
go vet ./... && go test -race ./...
go test ./path/to/pkg -run TestName   # single test
go test ./internal/transfer -run '^$' -fuzz FuzzUnpack -fuzztime 30s
```

Mobile (run from `mobile/`; bun is used, so prefer `bunx` over `npx`):

```bash
bun install
bun run start            # expo start (also: android)
bun run lint             # expo lint
bunx tsc --noEmit        # typecheck
bun run format:check     # prettier (bun run format fixes)
bun test src             # unit tests (bun:test)
# compile and unit-test the Kotlin module (needs JAVA_HOME=temurin 21, not the default Java 27):
#   bunx expo prebuild --platform android --no-install && cd android && ./gradlew :sharing-service:compileDebugKotlin :sharing-service:testDebugUnitTest
#   SHARINGD_BIN=/path/to/sharingd makes InteropTest drive a real daemon
bunx expo install <pkg>  # ALWAYS use instead of bun add - resolves SDK-compatible versions
bunx expo-doctor         # diagnose dependency/config issues
```

Run lint and typecheck before declaring mobile work done. `scripts/check-manifest.sh` asserts the merged release manifest after a Gradle build.

## Mobile conventions (from `mobile/AGENTS.md`)

- Expo changes breaking APIs every SDK: do not rely on memory. Check the `expo` major version in `package.json` and consult `https://docs.expo.dev/versions/v<major>.0.0/` (index: `https://docs.expo.dev/llms.txt`) before touching Expo/EAS/RN APIs.
- Navigation is Expo Router only. Every file in `src/app/` is a route (`_layout.tsx` defines navigators); keep components, hooks, and utils outside `src/app/` (e.g. in `src/lib/`).
- `ios/` and `android/` are generated (Continuous Native Generation) when absent — never create or edit them by hand; configure native behavior via `app.json` and config plugins.
- Expo Go only bundles certain native modules; after adding a library with native code use a development build (`bunx expo run:ios|android` or `bunx eas-cli build --profile development`).
- Prefer official Expo modules over third-party libraries. Builds/OTA go through EAS (`bunx eas-cli build|submit|update`).
- Mobile-first: prioritize performance. The product is Android only (the core is a Kotlin service and the daemon is Linux), so `ios` and `web` are not configured.
